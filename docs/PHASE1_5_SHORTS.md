# Phase 1.5: 実際のYouTube Shortsで縦型フィードを検証する

Phase 1 / Issue #1 / [Draft PR #7](https://github.com/Luke0703/knowledge-stream/pull/7)の追加検証です。ブランチは`feature/phase-1-player-spike`。目的は実際の縦型ShortsとiPhone Safariの相性を調べることで、Phase 2以降の機能は追加していません。

## 変更したコード

| ファイル | 変更と理由 |
| --- | --- |
| `src/videos.ts` | 公開Shorts 3本のURL・内部UUID・独自ラベルを一元管理。`source`からプレーヤー用`externalVideoId`を生成 |
| `src/player/youtubeUrl.ts` | 生ID、Shorts、watch、youtu.be、embed URLに対応。HTTP(S)と指定YouTubeホストに限定し、紛らわしいドメイン・認証情報付きURL・不正IDを拒否 |
| `src/styles.css` | カード内の残り高さと幅から9:16のプレーヤーサイズを決定。状態案内56pxを予約し、最大高さ640px・最低200×200pxを確保 |
| `src/App.tsx` | 検証版を識別できるよう上部に「SHORTS SPIKE · PHASE 1.5」と表示 |
| `tests/youtubeUrl.test.ts` | URL/ID抽出9ケース、拒否14ケース、3本の固定データ・UUID/外部ID分離の1ケースを追加 |

`YouTubePlayer`とAPIローダーは維持し、`VideoFeed`と`PlaybackCoordinator`には後述の音声操作を追加しました。CSS scroll-snap、カード65%以上かつプレーヤー50%以上のactive判定、現在±1本のロード、旧動画停止・範囲外destroy・非表示時の停止を維持します。Workerのhealthは引き続き`phase: 1`で、1.5専用APIは作りません。

## 9:16表示と公式UI

プレーヤー枠の高さは、親コンテナの高さから状態表示用56pxを引いた値、親幅×16/9、640pxの最小値です。幅は高さ×9/16です。CSSのcontainer query単位（cqh/cqw）を使い、ヘッダー・動画情報・外部リンク・前後操作・下部タブを除いた領域へ収めます。

短い画面では幅または高さを最低200pxまで広げるため、厳密な9:16にならないことがあります。映像の余白はYouTube公式プレーヤーが処理します。iframeの拡大クロップ、負の位置調整、独自UI・透明レイヤーの重ね合わせはしません。高さ620px未満は従来どおりページ全体をスクロールして下部へ移動します。横向きで全操作を同時に表示する設計ではありません。

`controls=1`、`playsinline=1`を維持。初期設定は音声オンで自動再生を試します。拒否時はYouTube標準の再生ボタンを押します。前/次・再試行・音声操作はiframe外にあります。動画内のスワイプが親ページへ伝わるとは仮定していません。

## 音声操作の追加検証

利用者からShorts版の「動きは完璧だと思う」との総合報告と、スマホでは標準のミュート解除ボタンが表示されず音声をオンにできなかったとの報告がありました。音声を出せなかったため、音声重複の実機確認が済んだとは扱いません。初期音声オンの希望に合わせ、以下を変更しました。

- 初期状態を音声オンに変更。音声付き自動再生が拒否されても、無断でミュートへ戻さず標準再生ボタンを案内します。
- `VideoFeed`のプレーヤー外に「音声オン／音声オフ」を追加。タップから同期的に公式APIの`unMute()` / `mute()`を呼びます。[YouTube公式APIの音量操作](https://developers.google.com/youtube/iframe_api_reference#Playback_controls)
- `PlaybackCoordinator.setMuted()`で可視・active・準備済みの対象だけを操作し、音声設定をページ内で保持。画面外・非active・破棄済みへの操作を無視し、音声操作だけでは再生を開始しません。
- この2ボタンは状態表示ではなく明示的な指示です。YouTube標準UIでのミュート変更は保持設定へ同期しません。ページ再読み込みで音声オンへ戻り、LocalStorageには保存しません。
- PC内蔵ブラウザで音声付き自動再生の拒否を実際に確認し、標準ボタンによる手動再生で「再生中」へ進むことを確認。外側のオフ→オン操作で公式UIの「ミュートを解除」→「ミュート」表示が変わることを確認しました。PC音声の聴取確認ではありません。
- 外側操作追加後も390×844・320×568で重なりなし。320×568のiframeは200×200px、音声操作行は44px。上記の初回計測サイズは音声操作追加前の記録です。
- 型チェック・build・39テスト成功。初期音声オン、外側操作の引き継ぎ、対象制限、手動停止維持を検証。修正版のiPhone音声出力は再確認待ちです。
