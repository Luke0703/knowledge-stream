# Knowledge Stream — 10/20 実装計画（2026-10-15版）

## ゴールと優先順位
**最優先: スマホで「ジャンル選択→YouTube動画フィード→スワイプ→検索」を体験でき、管理者が登録データを変更できること。**
完了目標は2026-10-20。検証されていない動作は「完了」に含めない。

### P0（プロトタイプ完成条件）
- React/TS/Vite + Cloudflare Worker SPA+API の動作基盤
- iPhone SafariでYouTube埋め込みと縦方向の切替、前後への移動方法を確認（プレーヤー上のスワイプ競合も）
- 初回のジャンル複数選択（OR）、フィード/検索/プロフィールの固定3タブ
- 端末内の視聴済み（動画active時）、未視聴優先、保存、興味なし
- D1とAPIの導入、独自ラベル/キーワードによる部分一致検索
- Cloudflare Accessで画面/管理APIを保護し、WorkerでJWT検証する管理画面（動画/ジャンルCRUD相当）
- 役立った/分類違いの匿名評価（重複制約・入力検証・レート制限）
- 埋め込み再生失敗時の再試行/スキップと自動再生拒否への対応
- local/staging/productionの分離、秘密情報の非コミット、migration、手動バックアップ手順、利用案内・プライバシー案内、最低限のテスト

### P1（P0を壊さず余裕があれば）
- 検索結果の利便性調整・Saved一覧UI改善
- 通報一覧やエラー集計の拡充
- Androidでの追加実機確認
- ダミー広告カード（標準プレーヤー領域外に独立表示）

### P2（10/20版では実施しない）
一般ユーザー投稿/ログイン、YouTube Data API、TikTok/Instagram、AI分類、独自動画アップロード、企業広告システム、複雑な推薦、KV/Queues/R2自動導入、独立マイクロサービス。

## 分担案
- 開発側: React/Worker/D1/管理画面/GitHub/テスト自動化
- コンテンツ側: 初期ジャンル、実在するYouTube動画URLと独自ラベル/検索キーワード、検証協力者、動画選定基準
- 両名: UI確認、管理者認証、iPhone/Android操作性、仕様レビュー

## 開発・レビューの進め方
1. mainは常にレビュー可能な状態を維持。機能ごとにfeatureブランチを作成。
2. Codexは**1Issueごと**に変更し、PR形式で説明・テスト結果・未確認事項を記載。
3. 実機検証とCloudflare認証/デプロイにはユーザー自身の確認操作が必要になる場合がある。秘密鍵をチャット/GitHubへ貼らない。
4. main反映前に少なくとも型チェック/build/関連テスト。stagingで動作後にproduction。
5. **YouTube iframe内のスワイプ操作**は実機の挙動が確認できるまで実装方式を固定しない。プレーヤーを透明UIで覆う解決策は不可。
